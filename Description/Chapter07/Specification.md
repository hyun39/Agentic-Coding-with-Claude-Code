# Chapter 07: Working with Claude Code Subagents

## 📌 개요
이 챕터는 복잡하고 규모가 큰 작업을 효율적으로 처리하기 위한 **서브에이전트(Subagents)**의 활용법을 다룹니다. 모든 작업을 단일 컨텍스트에서 처리하는 대신, 특정 도메인에 특화된 페르소나와 지침을 가진 독립적인 에이전트에게 작업을 위임(Delegation)함으로써 정확도를 높이고 컨텍스트 관리를 최적화하는 '에이전트 오케스트레이션' 기법을 실습합니다.

## 🌳 디렉토리 구조
```text
Chapter07/
├── .claude/
│   └── agents/                     # 서브에이전트 정의 파일 저장소
│       ├── code-comedy-carl.md      # 코드를 코믹하게 리뷰하는 에이전트
│       └── mermaid-diagram-generator.md # 기술 문서를 다이어그램으로 변환하는 에이전트
├── main.py                         # 서브에이전트의 작업 대상이 되는 샘플 소스 (피보나치)
└── README.md                       # Claude Code 활용 가이드
```

## ⚙️ 파일별 역할 및 부재 시 영향 (Impact Analysis)

| 파일/폴더명 | 역할 | 삭제/부재 시 발생하는 현상 |
| :--- | :--- | :--- |
| **`.claude/agents/`** | 프로젝트 전용 서브에이전트들의 명세 파일이 모여 있는 폴더 | 메인 에이전트가 작업을 위임할 대상을 찾지 못해 모든 작업을 직접 처리해야 하며, 전문적인 결과물(예: 복잡한 다이어그램)의 품질이 저하될 수 있습니다. |
| **`mermaid-diagram-generator.md`** | Mermaid 문법과 시각화 전략에 정통한 전문가 에이전트 정의 | 사용자가 아키텍처 다이어그램 작성을 요청했을 때, 일반 모델이 시각적 구조보다 텍스트 설명에 치중하는 결과를 낳을 수 있습니다. |
| **`code-comedy-carl.md`** | 특정 페르소나(유머러스한 개발자)를 가진 에이전트 정의 | 에이전트의 강점인 '역할극을 통한 특수 목적 달성(재미있는 리뷰 등)' 실습이 불가능해집니다. |
| **`main.py`** | 에이전트들이 분석하고 가공할 대상 소스 코드 | 에이전트가 다이어그램을 그리거나 리뷰할 "맥락"이 사라져 실질적인 위임 워크플로우를 테스트할 수 없습니다. |

## 💡 핵심 학습 개념

### 1. 에이전트 위임 (Delegation)
- 메인 에이전트가 "내가 직접 하기보다 이 전문가에게 맡기는 게 낫겠다"고 판단하도록 유도합니다.
- `.claude/agents/`에 저장된 에이전트들은 메인 에이전트의 도구 상자에 추가되어 언제든 호출 가능한 상태가 됩니다.

### 2. 전문화된 페르소나 (Specialized Personas)
- **Mermaid Specialist**: 일반적인 코딩 지식보다 다이어그램 문법과 시각적 레이아웃에 최적화된 지침을 보유합니다.
- **Comedy Carl**: 단순히 정보를 전달하는 것을 넘어, 특정 톤과 스타일을 유지하도록 설계된 페르소나의 예시입니다.

### 3. 컨텍스트 격리 (Context Isolation)
- 서브에이전트는 자신만의 독립된 대화 창을 가집니다. 이는 메인 세션의 토큰 한계를 넘어서는 정밀한 작업이 가능하게 합니다.

## 🚀 실습 절차
1. **서브에이전트 호출**: Claude Code에서 `main.py`를 보여준 뒤 "이 코드를 다이어그램으로 그려줘"라고 요청합니다.
2. **오케스트레이션 관찰**: 메인 에이전트가 `mermaid-diagram-generator`를 실행하여 결과를 가져오는 과정을 모니터링합니다.
3. **결과 검증**: 생성된 Mermaid 코드가 정확한지, 서브에이전트의 지침(No Fluff, Only Diagram)이 잘 지켜졌는지 확인합니다.

## ✅ 결론 및 권장 사항
- **역할의 명확한 정의**: 서브에이전트의 `description` 필드는 메인 에이전트가 "언제" 이 에이전트를 써야 할지 결정하는 핵심 데이터입니다. 명확하고 구체적인 few-shot 예제를 포함하십시오.
- **모듈형 설계**: 복잡한 기능을 하나의 메인 프롬프트에 담지 말고, 작은 단위의 전문 서브에이전트로 쪼개서 관리하는 것이 유지보수에 유리합니다.
