# Chapter 01: Optimizing MCP Context for Claude Code

## 📌 개요
이 챕터는 Claude Code의 **컴퓨팅 효율성**과 **컨텍스트 최적화**를 다룹니다. 특히 여러 MCP(Model Context Protocol) 서버를 동시에 사용할 때 발생하는 토큰 낭비 문제를 분석하고, 작업별 전용 설정을 통해 이를 해결하는 방법론을 제시합니다.

## 🌳 디렉토리 구조
```text
Chapter01/
├── .mcp.json               # 기본 범용 MCP 설정
├── .mcp.json.tavily        # Tavily 전용 최소화 MCP 설정
├── .python-version         # 프로젝트 권장 Python 버전
├── main.py                 # 프로젝트 진입점 (연습용)
├── pyproject.toml          # 의존성 정의 (uv/pip용)
├── uv.lock                 # 고정된 종속성 버전 정보
├── verbose_mcp_server.py   # 실습용 Verbose MCP 서버 구현체
└── README.md               # 챕터 지침서
```

## ⚙️ 파일별 역할 및 부재 시 영향 (Impact Analysis)

| 파일명 | 역할 | 삭제/부재 시 발생하는 현상 |
| :--- | :--- | :--- |
| **`.mcp.json`** | 모든 MCP 서버(Verbose, Tavily 등)를 로드하는 기본 설정 파일 | Claude Code 실행 시 기본 도구들을 사용할 수 없으며, 컨텍스트 비대화 시연이 불가능합니다. |
| **`.mcp.json.tavily`** | 리서치 전용 최소화 설정 파일 | `--mcp-config` 플래그를 이용한 **컨텍스트 최적화 실습**을 진행할 수 없습니다. |
| **`verbose_mcp_server.py`** | 의도적으로 장황한 설명을 가진 로컬 MCP 서버 | 이 챕터의 핵심인 **'컨텍스트 오염(Context Pollution)'** 현상을 눈으로 확인하고 측정할 대상이 사라집니다. |
| **`pyproject.toml`** | 프로젝트 환경 및 라이브러리 의존성 정의 | `mcp`, `fastmcp` 등 필요한 라이브러리를 설치할 수 없으며, 로컬 MCP 서버 실행 자체가 실패합니다. |
| **`main.py`** | 코드 분석 및 편집 실습을 위한 더미 소스 | Claude Code가 분석할 대상 파일이 없으므로, 파일 기반의 어시스턴스 기능을 테스트할 수 없습니다. |

## 💡 핵심 학습 개념

### 1. 컨텍스트 오염 (Context Pollution)
- 범용 설정을 사용하여 무관한 MCP 서버를 모두 로드하면, 수만 개의 토큰이 도구 정의 및 설명으로 소비됩니다.
- 이는 비용 증가뿐만 아니라 모델의 추론 성능 저하(중요 정보 누락 가능성)를 초래합니다.

### 2. 점진적 공개 및 최소화 전략
- **`--mcp-config` 플래그 활용**: 세션 시작 시 필요한 특정 설정 파일만 지정하여 실행합니다.
  ```bash
  claude --mcp-config .mcp.json.tavily
  ```
- **작업별 분리**: 리서치용, 테스트용, 배포용 등 목적에 따라 `.mcp.json.*` 파일을 분리하여 관리합니다.

## 🚀 실습 절차
1. **Verbose Server 실행**: 장황한 설명을 가진 서버를 통해 `/context` 명령어로 토큰 소모량을 확인합니다.
2. **범용 설정 문제 확인**: 모든 서버 로드 시 발생하는 급격한 토큰 상승을 모니터링합니다.
3. **최적화 설정 적용**: `.mcp.json.tavily`와 같이 필요한 서버만 로드하여 컨텍스트 창을 깨끗하게 유지합니다.

## ✅ 결론 및 권장 사항
- **기본값은 무겁다**: 기본 설정을 맹신하지 말고 항상 `/context`로 모니터링하십시오.
- **최소 권한 원칙**: 에이전트에게 꼭 필요한 도구만 제공하는 것이 정확도를 높이는 핵심입니다.
- **설정의 파편화**: 프로젝트 루트에 다양한 워크플로우용 설정 파일을 두는 것을 두려워하지 마십시오.
