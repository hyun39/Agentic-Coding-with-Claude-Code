# Chapter 10: Using Claude Code Desktop

## 📌 개요
이 챕터는 터미널 중심의 CLI 환경을 넘어, **Claude 데스크톱 애플리케이션**과 IDE 연동을 통한 고도화된 개발 환경을 다룹니다. 특히 여러 작업을 동시에 진행할 때 발생하는 맥락 혼선을 방지하기 위해 가상 세션이나 Git Worktree를 활용하여 에이전트들에게 병렬 작업을 할당하는 '멀티 에이전트 병렬 워크플로우'를 실습합니다.

## 🌳 디렉토리 구조
```text
Chapter10/
├── vigilant-feistel/           # 병렬 작업 세션 A (예: UI 개선 브랜치)
│   └── hookhub/                # 해당 세션의 전용 코드 저장소
└── zealous-jemison/            # 병렬 작업 세션 B (예: 리팩토링 브랜치)
    └── hookhub/                # 해당 세션의 전용 코드 저장소
```

## ⚙️ 파일별 역할 및 부재 시 영향 (Impact Analysis)

| 파일/폴더명 | 역할 | 삭제/부재 시 발생하는 현상 |
| :--- | :--- | :--- |
| **세션 폴더 (`vigilant-feistel` 등)** | 독립적인 개발 컨텐스트 및 브랜치 작업 영역 | 여러 에이전트가 단일 폴더에서 충돌 없이 동시에 다른 작업을 수행하는 '병렬화' 시나리오를 구현할 수 없습니다. |
| **`hookhub` (세션 내 복제본)** | 병합 전까지 독립적으로 수정되는 코드베이스 | 에이전트 간의 독립적인 도구 실행과 테스트가 불가능해지며, 코드 간섭(Overwrite) 위험이 커집니다. |
| **`CLAUDE.md`** | 데스크톱 환경 내 에이전트 통제 지침 | 터미널 밖의 GUI 환경에서도 에이전트가 일관된 규칙(빌드 방식, 스타일 가이드 등)을 준수하게 만드는 '닻' 역할이 사라져 구현 일관성이 깨집니다. |

## 💡 핵심 학습 개념

### 1. 병렬 개발 워크플로우 (Parallel Development)
- 단일 에이전트와 순차적으로 대화하는 대신, 여러 개의 데스크톱 세션을 띄워 기능을 동시 개발합니다.
- 각 세션은 고유한 이름을 가지며(예: `vigilant-feistel`), 이는 에이전트 작업의 추적성을 높입니다.

### 2. Git Worktree: 병렬 개발의 마법사
- **정의**: 하나의 Git 저장소(`.git` 폴더)를 공유하면서, 여러 개의 독립된 작업 디렉토리(Working Tree)를 생성하여 서로 다른 브랜치를 동시에 체크아웃할 수 있게 해주는 Git의 고급 기능입니다.
- **에이전틱 개발에서의 핵심 역할**:
    - **컨텍스트 완전 격리**: 에이전트 A는 `feature-ui` 폴더에서, 에이전트 B는 `feature-api` 폴더에서 동시에 작업할 수 있습니다. 한 폴더에서 브랜치를 바꾸며(`git checkout`) 발생하는 파일 변경 혼란이 없습니다.
    - **중복 리소스 방지**: 매번 서버 전체를 `clone`할 필요 없이, 기존 저장소의 데이터를 공유하므로 디스크 공간을 절약하고 즉각적인 세션 생성이 가능합니다.
    - **UI 자동화의 용이성**: 각 워크트리는 독립된 로컬 서버 포트를 가질 수 있어, 에이전트들이 각기 다른 브랜치의 UI를 동시에 띄워놓고 시각적 검증을 할 수 있습니다.
- **주요 명령어**:
  ```bash
  # 'new-feature' 브랜치를 '../feature-session' 디렉토리에 워크트리로 생성
  git worktree add ../feature-session new-feature
  ```

### 3. 클라우드 연동 및 모바일 제어
- 데스크톱 앱을 통해 에이전트를 클라우드 인스턴스에 올리고, 모바일 기기 등에서도 작업 진행 상황을 모니터링하거나 지시를 내리는 전체 생태계를 이해합니다.

## 🚀 실습 절차
1. **독립 세션 생성**: 데스크톱 앱에서 서로 다른 작업 의도를 가진 두 개의 세션을 생성합니다.
2. **병렬 작업 지시**: 세션 A에는 UI 수정을, 세션 B에는 백엔드 최적화를 지시합니다.
3. **통합 및 검증**: 각 세션에서 에이전트가 완료한 브랜치들을 메인으로 병합하며 충돌 여부 및 통합 테스트를 수행합니다.

## ✅ 결론 및 권장 사항
- **조정(Orchestration)의 가치**: 데스크톱 환경은 단순한 화면 제공을 넘어, '동시 다발적인 에이전트의 움직임'을 시각적으로 관리하고 통제하는 관제 센터 역할을 합니다.
- **인프라로서의 에이전트**: 로컬 자원을 넘어 클라우드 컨테이너와 연동된 데스크톱 앱은 물리적 기기 사양에 구애받지 않는 안정적인 '24시간 무중단 개발 에이전트' 구축을 가능케 합니다.
