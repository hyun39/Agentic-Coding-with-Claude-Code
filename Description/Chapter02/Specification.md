# Chapter 02: The GIST of Claude Code

## 📌 개요
이 챕터는 Claude Code가 낯선 프로젝트의 **시스템과 기술적 통찰(GIST)**을 확보하는 과정을 다룹니다. 단순히 코드를 수정하는 것이 아니라, 프로젝트의 아키텍처를 이해하고, 명세(Spec)에 기반해 작업하며, 작업 상태를 메모리에 저장하여 일관성을 유지하는 '에이전틱 개발 워크플로우'를 실습합니다.

## 🌳 디렉토리 구조 (hookhub 기준)
```text
Chapter02/hookhub/hookhub/
├── .claude/                # 에이전트 로컬 설정
├── CLAUDE.md               # 프로젝트 가이드라인 (핵심!)
├── memory/                 # 에이전트의 지속성 데이터 저장소
│   ├── frontend/           # 프론트엔드 작업 관련 메모리
│   └── spec/               # 명세 관련 분석 메모리
├── specs/                  # 명세서 기반 개발을 위한 문서
│   └── hero.spec.md        # 히어로 섹션 구현 상세 명세
├── src/                    # Next.js 애플리케이션 소스 코드
├── package.json            # 프로젝트 의존성 및 스크립트 정의
└── README.md               # 프로젝트 시작 가이드
```

## ⚙️ 파일별 역할 및 부재 시 영향 (Impact Analysis)

| 파일/폴더명 | 역할 | 삭제/부재 시 발생하는 현상 |
| :--- | :--- | :--- |
| **`CLAUDE.md`** | 프로젝트 개요, 빌드/테스트 명령어, 코딩 컨벤션 정의 | 에이전트가 매번 빌드 방식이나 아키텍처를 물어보게 되어 작업 속도가 저하되고 규칙 미준수 위험이 커집니다. |
| **`specs/`** | 구현해야 할 기능의 논리적 아키텍처와 상세 요구사항 기술 | 에이전트가 전체 맥락 없이 코드만 수정하게 되어, 비즈니스 로직의 의도와 어긋난 구현을 할 가능성이 높습니다. |
| **`memory/`** | 이전 작업의 상태, 결정 사항, 스크린샷 등을 기록 | 세션이 끊겼을 때 에이전트가 "어디까지 했는지" 잊어버리게 되어 중복 작업을 하거나 처음부터 다시 분석해야 합니다. |
| **`src/`** | 실제 동작하는 Next.js 15 기반의 코드베이스 | 분석 및 수정할 대상 시스템 자체가 사라지므로 물리적인 개발 실습이 불가능합니다. |
| **`package.json`** | 프로젝트 실행을 위한 스크립트(`dev`, `build` 등) 정의 | `CLAUDE.md`에 정의된 '명령어'가 작동하지 않아 에이전트가 앱을 실행하거나 테스트할 수 없습니다. |

## 💡 핵심 학습 개념

### 1. CLAUDE.md: 에이전트의 지도
- 에이전트가 런타임에 가장 먼저 참조하는 문서입니다.
- **Essential Commands**: 에이전트가 스스로 앱을 실행하고 검증할 수 있는 수단을 제공합니다.
- **Architecture**: 기술 스택(Next.js 15, Tailwind 4 등)과 디렉토리 구조를 명시하여 탐색 효율을 높입니다.

### 2. 명세 중심 개발 (Spec-driven Development)
- `specs/hero.spec.md`와 같은 문서를 먼저 작성하고 에이전트에게 이를 읽게 함으로써 환각(Hallucination)을 줄이고 정확한 구현을 유도합니다.

### 3. 지속성 (Persistence)
- `memory/` 폴더는 에이전트가 "생각의 흐름"이나 "진행 상태"를 파일로 기록하는 공간입니다. 이는 대규모 프로젝트에서 컨텍스트 윈도우 한계를 극복하는 전략입니다.

## 🚀 실습 절차
1. **프로젝트 로드**: `hookhub` 폴더에서 Claude Code 실행.
2. **지침 확인**: `CLAUDE.md`를 통해 프로젝트 규칙 습득 확인.
3. **명세 분석**: `specs/hero.spec.md`를 바탕으로 구현 계획 수립.
4. **구현 및 기록**: 코드 수정 후 진행 상황을 `memory/`에 업데이트.

## ✅ 결론 및 권장 사항
- **환경 구축의 자동화**: `CLAUDE.md`는 에이전트뿐만 아니라 신규 개발자를 위해서도 필수적입니다.
- **기록하는 습관**: 에이전트가 작업 중간 결과를 `memory/`에 기록하도록 프롬프팅하는 것은 긴 작업 흐름에서 매우 중요합니다.
